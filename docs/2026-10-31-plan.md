# Plan: Stepdown Rule — Adoption & Capability Roadmap

Date: 2026-10-31
Branch: camp/decide-next
Source: docs/2026-10-31-idea-slate.md (ranked idea slate)

## 1. Goals & non-goals

### Goals
- Make stepdown-rule adoptable in existing codebases without "fix everything first" (baseline + inline disables).
- Close the feature-completeness gap that limits applicability (class/object methods, TSX).
- Make the dev loop fast (watch mode, incremental cache, parallelism, diff-only).
- Make CI integration first-class (SARIF, severity, stats, graceful parse errors).
- Keep the tool ergonomic (config check/extends, .stepdownignore, completions, color control, progress).
- Preserve existing contracts: agents JSON envelope, exit codes, rule registry, IFileService seam, reporter seam.

### Non-goals
- No new language targets (Vue/Svelte/Astro) in this plan.
- No full LSP server (deferred P4; design only).
- No cross-file analysis in this plan (deferred P4).
- No telemetry by default (opt-in only, separate bead).
- No breaking changes to public API without a migration note.

## 2. Success criteria

- A codebase with 1000+ pre-existing violations can adopt stepdown-rule in CI in < 1 hour using baseline + inline disables, with only *new* violations failing.
- `stepdown-rule --watch` re-analyzes a changed file in < 500 ms on a 500-file project.
- `--format sarif` output validates against the SARIF 2.1.0 schema and uploads to GitHub code scanning without errors.
- Class methods and TSX files are analyzed without crashes; at least one fixture per pattern.
- All new features have unit + integration tests; `br dep cycles` empty; `bun run vet` green.
- No regression in existing 24 test files.

## 3. Architecture decisions

### AD-1: Baseline file format
JSON file (`.stepdown-baseline.json`) with schema:
```
{
  "version": 1,
  "generatedAt": ISO8601,
  "toolVersion": "x.y.z",
  "entries": [
    { "file": "src/foo.ts", "rule": "stepdown", "function": "bar", "line": 12, "hash": "sha256:..." }
  ]
}
```
Hash = sha256 of (file path + rule + function name + normalized violation signature). Matching is by hash first, then (file, rule, function) fallback. Baseline entries are not "deleted" on fix; `--update-baseline` regenerates from current state. Suppressed violations are reported in `--verbose` as "baseline-suppressed: N".

### AD-2: Inline disable grammar
Support three forms, parsed from leading trivia of the offending statement/function:
- `// stepdown-disable-next-line [rule[,rule]]`
- `// stepdown-disable-line [rule[,rule]]`
- `/* stepdown-disable */ ... /* stepdown-enable */` (block)
No rule list = all rules. Disable is scoped to the statement it precedes (next-line) or the block. Fixer must skip disabled violations (do not reorder disabled functions). Record disables in `--verbose` count.

### AD-3: Watch mode
Use `fs.watch` (recursive where supported) with debounce 150 ms. Re-run analysis only on changed files (plus dependents if cross-file later; for now file-local). Keep process alive; exit on Ctrl-C. Print delta: "N new, M resolved, K remaining". Compose with incremental cache (AD-4) and parallelism (AD-5).

### AD-4: Incremental parse cache
Disk cache under `.stepdown-cache/` (gitignored, auto-created). Key = sha256(filePath + mtime + size + configHash + toolVersion). Value = serialized AnalysisResult (JSON, no SourceFile). On hit, skip parse. `--no-cache` disables; `--clear-cache` wipes. Cache is per-project (rooted at config file or cwd).

### AD-5: Parallelism
Worker pool sized to `min(cpuCount, 8)` by default, `--jobs N` override. Each worker gets a file + config; returns AnalysisResult. Main thread aggregates. Fallback to sequential if workers unavailable (e.g., single file). Requires serializable config (already is).

### AD-6: Severity
Config: `"rules": { "stepdown": "error", "nested": "warn" }` (or array form preserved). Default all "error". Exit code: 0 if no error-severity violations (warnings allowed unless `--max-warnings N` exceeded); 1 if errors or warnings over threshold; 2 usage error. Compose with baseline (baseline-suppressed never counts).

### AD-7: SARIF
Implement a SARIF 2.1.0 log with one run, one tool component, results per violation. `ruleId`, `level` (from severity), `message`, `locations` (file + region from line/col), `partialFingerprints` (baseline hash) for dedup. Validate against schema in tests.

### AD-8: Class/object method support
Extend AST visitors to collect methods from `ClassDeclaration`/`ClassExpression` and object literal methods. Reorder within the class body using the same topological logic, but:
- Respect method modifiers (static vs instance) — only reorder within same modifier group.
- Never reorder lifecycle-named methods (constructor, ngOnInit, etc.) — keep an allowlist of "pinned" names.
- Default off unless `--include-methods` or config `analyzeMethods: true`, because method order often carries intent.
Ship behind a flag first; promote to default after fixture + user feedback.

### AD-9: TSX/JSX
Switch parser to `ts.createSourceFile(path, text, ScriptTarget.Latest, true, path.endsWith("x") ? ScriptKind.TSX : ScriptKind.TS)`. Ensure JSX expressions inside functions don't break call-graph extraction (they shouldn't; TS handles). Add `.tsx`/`.jsx` to default globs.

### AD-10: Inline disable parsing
Read leading trivia of the statement containing the violation. Use `ts.getLeadingCommentRanges`. Match regex `/stepdown-disable-(next-)?line(?:\s+([\w,-]+))?/`. Block form via scanning for `stepdown-disable`/`stepdown-enable` markers with nesting depth.

## 4. Task breakdown (epics → tasks)

### Epic E1 — Adoption foundation (baseline + disables + severity)
**Goal:** Make existing codebases adoptable.
**Depends on:** none (foundation).
**Tasks:**
- T1.1 Implement baseline file read/write + matching (AD-1). Subtasks: schema, hash, matcher, `--baseline <path>`, `--update-baseline`.
- T1.2 Implement inline disable parsing (AD-2) + fixer skip. Subtasks: trivia parser, block form, rule scoping, tests.
- T1.3 Severity config + exit codes (AD-6). Subtasks: config schema, CLI flag, `--max-warnings`, reporter update.
- T1.4 Wire baseline + disables into agents envelope (suppressed counts). Depends on T1.1, T1.2.
- T1.5 Golden tests for baseline/disable output. Depends on T1.1–T1.3.

### Epic E2 — Dev loop (watch + cache + parallelism + diff-only)
**Goal:** Fast feedback.
**Depends on:** E1 (for incremental correctness) loosely; cache independent.
**Tasks:**
- T2.1 Incremental parse cache (AD-4). Subtasks: cache key, read/write, invalidation, `--no-cache`/`--clear-cache`.
- T2.2 Parallel file processing (AD-5). Subtasks: worker pool, serialization, fallback, `--jobs`.
- T2.3 Watch mode (AD-3). Depends on T2.1, T2.2. Subtasks: fs.watch, debounce, delta reporting, graceful exit.
- T2.4 Diff-only mode (`--changed-since`). Subtasks: git diff --name-only integration, path filtering.
- T2.5 Progress reporting (stderr) + `--no-progress`/`--quiet`. Independent.

### Epic E3 — CI integration (SARIF + stats + graceful errors + determinism)
**Goal:** First-class CI citizen.
**Tasks:**
- T3.1 SARIF output (AD-7). Subtasks: mapper, schema validation test, `--format sarif`.
- T3.2 `stats` command. Subtasks: aggregator, text + JSON output.
- T3.3 `explain` command (call chain). Subtasks: dependency path finder, formatter, `--json`.
- T3.4 Graceful parse-error handling. Subtasks: try/catch per file, parseErrors array, exit code.
- T3.5 Deterministic output ordering. Subtasks: sort violations, stable JSON key order.

### Epic E4 — Feature completeness (class methods + TSX)
**Goal:** Analyze real-world TS.
**Tasks:**
- T4.1 TSX/JSX parser switch (AD-9). Subtasks: ScriptKind, default globs, fixtures.
- T4.2 Class/object method collection (AD-8) behind `--include-methods`/config. Subtasks: visitors, modifier grouping, pinned-name allowlist, reorder.
- T4.3 Fixer support for method reordering (only when enabled). Depends on T4.2.
- T4.4 Fixtures + tests for classes/TSX.

### Epic E5 — Ergonomics & config (validation, extends, ignore, completions, color)
**Goal:** Polish.

- T5.2 Config `extends`.

- T5.5 Color control (NO_COLOR, `--color`, `--quiet`) — note: `--quiet` shared with T2.5; coordinate.

## 6. Risks & mitigations

- R1: Baseline hash instability across TS versions → mitigate: hash includes only stable fields (file/rule/function/line), not printer output; version the baseline schema.
- R2: Inline disable parsing of trivia is fragile across TS versions → mitigate: use official `getLeadingCommentRanges`; add tests per TS version in matrix.
- R3: Watch mode + cache invalidation bugs cause stale results → mitigate: cache key includes mtime+size+config+tool version; watch always re-reads changed file.
- R4: Parallel workers + Bun worker API instability → mitigate: feature-detect; fallback to sequential; keep worker boundary narrow (file in, result out).
- R5: Class method reordering changes semantics (lifecycle) → mitigate: opt-in flag + pinned-name allowlist + tests; default off.
- R6: SARIF schema drift → mitigate: validate against official schema in CI test.
- R7: Plugin API security (arbitrary code load) → mitigate: only load from explicit config paths; document trust model; no auto-discovery.

## 7. Testing strategy

- Unit: each new module gets a unit test file (mirror existing pattern).
- Integration: CLI-level tests via cli-harness for new flags/commands.
- Golden: committed expected stdout for fixture files under tests/goldens.
- Property/fuzz: random TS snippets for parser + fixer idempotency.
- Perf: benchmark suite with thresholds; CI fails on >20% regression.
- Mutation: fixer mutation score target ≥ 80%.

## 8. Rollout

- Phase A (E1): ship baseline + disables + severity as 0.5.0 (minor, additive).
- Phase B (E2+E3): ship dev loop + CI as 0.6.0.
- Phase C (E4): ship class/TSX support as 0.7.0 (flagged default-off for methods).
- Phase D (E5+E6+E7): polish + ecosystem as 0.8.0.
